# Серверная часть — что сделать

Папка для серверного кода (обработчики форм, заказы, оплата). Ключи и пароли сервисов храните в настройках сервера,
**не в коде страниц и не в репозитории**.

## 1. Заявки из форм

- Принять POST (FormData) с адреса из `data-action` формы: `name`, `phone`, `topic`, `what`, `via`, `msg`, `agree`.
- Сохранить заявку и отправить в CRM / на почту / в Telegram администратору.
- Ответ `200` — форма показывает «Заявка отправлена»; любой другой — сообщение об ошибке.
- Защита от спама: скрытое поле-ловушка или капча на сервере, ограничение частоты.

## 2. Заказ и оплата (корзина)

- `POST` JSON заказа (см. `../tz/03-korzina.md`).
- Пересчитать: цену каждой позиции по своему каталогу, скидки, промокод, лимиты мест на мероприятиях.
- Создать заказ и платёж в интернет-эквайринге банка; вернуть `{"paymentUrl": "…"}`.
- Принять уведомление банка об оплате (webhook), отметить заказ оплаченным, отправить чек (54-ФЗ) и письмо покупателю,
  уменьшить число свободных мест на мероприятии. При нуле мест — состояние мероприятия «Мест нет».
- Адрес возврата после оплаты: `spasibo.html?order=<номер>`.

## 3. Промокоды

- Проверка кода: существует ли, срок действия, тип скидки (процент / сумма), на какие позиции действует, лимит использований.
- Ответы для страницы: «применён», «не найден», «срок действия истёк».

## 4. Загруженность зала («в зале» в шапке)

- `GET` адрес из `data-endpoint` у `#occ` → JSON
  `{"count": 23, "capacity": 120, "updated": "2026-10-14T15:20:00+03:00", "hourly": [ожидаемое число людей по часам 0–23]}`.
- Данные — из CRM скалодрома через свой сервер (ключ CRM не на странице). Пока адрес пустой — показываются демо-данные с пометкой «Демо».

## 5. Мероприятия

- Автоматический перевод в архив по полю «дата ухода в архив»: кнопка «Уже прошло», страница в блоке «Прошедшие мероприятия».
